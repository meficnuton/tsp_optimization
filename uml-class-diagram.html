Strategy pattern — the core design

  • • TSPSolver is the abstract strategy: one uniform solve(problem, config) contract
  • • GreedySolver & GeneticAlgorithm are interchangeable implementations
  • • A parallel SolverConfig hierarchy carries per-algorithm parameters polymorphically
  • • The benchmark selects algorithms at runtime via TSPSolver* — no switch on type

Data flow

  • • MatrixLoader parses TSPLIB files (9 edge-weight types: EUC/MAN/MAX 2D+3D, CEIL_2D, GEO, ATT)
  • • TSPProblem::fromTspFile() delegates parsing, then wraps the dense distance matrix + tourCost()
  • • A solver consumes the problem and returns SolverResult (tour, cost, time_ms, gap vs reference)
  • • Note: _MatrixLoader_attached.* is an exact duplicate of MatrixLoader.* (kept for reference)

Benchmark framework

  • • _benchmark_*.cpp mains scan data/*.tsp and build BenchmarkCase lists with reference optima
  • • Each {solver, config, label} triple registers as a BenchmarkSolver
  • • runBenchmark() executes every solver × case × run, emitting BenchmarkResult rows
  • • writeBenchmarkStdout / writeBenchmarkCsv produce the files in results/
